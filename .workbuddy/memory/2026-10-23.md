## 关闭登录验证码（已实现并实测）

**原逻辑没有"关闭"选项**：`captcha.open-captcha`
- `0` = 每次登录都要（最严格，不是关闭）
- `N>0` = 同一 IP 密码错误 N 次后才要
- 负数 = 原来没有这个分支

**改动 3 个文件**：
1. `server/api/v1/system/sys_captcha.go` — 新增 `captchaRequired(c *gin.Context) bool`，三态 switch：负数→false / 0→true / 正数→比对失败计数。`Captcha()` 改用它。
2. `server/api/v1/system/sys_user.go` — `Login()` 里删掉重复的 Get/Set/判断，改调 `captchaRequired(c)`。
   - 之前两处逻辑各写一遍，改一处漏一处就会出现「前端不显示、后端仍校验」的错位，故抽公共函数。
3. `server/config/captcha.go` — tag 注释补充负数语义。

**配置**：`server/config.yaml` → `captcha.open-captcha: -1`

**前端不用改**：`web/src/view/login/index.vue:51` 用 `v-if="loginFormData.openCaptcha"`，
值来自 `/base/captcha` 返回的 `openCaptcha` 字段，后端返回 false 就自动隐藏。

**验证结果（8899 临时实例）**：
- `open-captcha: -1` → `openCaptcha=False`，不传 captcha 登录 `code=0 登录成功`
- `open-captcha: 0` → `openCaptcha=True`，不传 captcha 报 `code=7 验证码错误`（原逻辑未破坏）

## 【重要环境坑】Windows 上 viper 热更新对 sed -i 无效

`core/viper.go` 有 `v.WatchConfig()` + `OnConfigChange`，但用 `sed -i` 改 config.yaml
（Git Bash 下是「写临时文件再改名」）**不会触发 fsnotify**，配置不会热更新。

实测：改成 0 后 `openCaptcha` 仍是 False，必须重启进程才生效。
→ 结论：**改 config.yaml 后一律重启，别指望热更新**。
（`SetSystemConfig` 后台页面保存走的是 viper 自己的 WriteConfig，机制不同但同样建议重启验证。）

## 七牛云配置要点（调研结论，未实际接）

- `system.oss-type: qiniu` 才是开关；只填 qiniu 段不生效，`NewOss()` 的 default 会**静默回退 local**。
- **框架自带拼写 bug**：`git show HEAD:server/config.yaml` 里 zone 默认值是 `ZoneHuaDong`（大写 D），
  而 `utils/upload/qiniu.go:83` 的 switch 只认 `ZoneHuadong`（小写 d）。合法值仅 5 个：
  ZoneHuadong / ZoneHuabei / ZoneHuanan / ZoneBeimei / ZoneXinjiapo。
- `img-path` 结尾不能带 `/`，代码是 `ImgPath + "/" + ret.Key`。
- `use-https` 只管上传请求，返回 URL 的协议由 `img-path` 决定。
- 上传 key 格式 `时间戳+原文件名`，无目录层级。
- 七牛 SDK `github.com/qiniu/go-sdk/v7` 已在 go.mod（v7.25.2），无需额外 go get。

## 顺带确认的 config 结论

- `core/viper.go:40` 强制 `AutoCode.Root = filepath.Abs("..")`，yaml 里写什么都没用。
- `cors` 整段是死配置：`initialize/router.go:57-58` 两行 Use 都被注释，跨域靠 Vite proxy。
- `jwt.signing-key` 在 `/init` 时由 `uuid.New().String()` 随机生成，重装数据库会全员掉线。
- `zap.retention-day: -1` = 日志永不清理。
