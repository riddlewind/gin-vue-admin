## 修复：粘贴图片报「不是合法 JSON」（eye 用了纯文本模型）

### 真正的根因
`modelForMode` 把 `ai` 和 `eye` 归到同一档，都吃 `ai-codegen-model`。当时配的是
`deepseek-v4-flash`，而该模型 `/v1/models` 里 `input_modalities` **只有 text**。
网关对纯文本模型不报错、直接丢掉 image_url 内容，模型只看到「请识别这张图片」这句话，
于是回一句「我无法从图片中识别字段」。前端拿到这句话当需求描述再发给 ai，
最后报的是 JSON 解析失败——离真正原因隔了三层。

查多模态能力的最快办法：拉 `/v1/models`，看每个模型的 `input_modalities` 里有没有 `image`。
本中转站只有 `sensenova-6.8-flash-lite` 含 image。

### 改动
1. `config/auto_code.go` 新增 `AiVisionModel`（键 `ai-vision-model`）。
2. `modelForMode` 拆三档：ai→ai-codegen-model、eye→ai-vision-model、其它→ai-model，留空各自回落 ai-model。
3. `checkEyeDescription()`：eye 返回空或含拒绝话术（无法识别/请提供/抱歉/空白…）直接报错，
   错误直接指向 `ai-vision-model` 配错，不再让前端拿道歉文本去链式调用。
4. 前端 `autoCode/index.vue`：粘贴与选文件两条路径合并成 `recognizeImageToAutoCode()`，
   eye 失败或返回空就不往下调 ai（原来只有 `if (res.code===0)`，异常路径静默）。
5. `config.yaml` 加 `ai-vision-model: "sensenova-6.8-flash-lite"`（`ai-codegen-model` 保持 deepseek-v4-flash）。

## 429 限流：自动重试 + 人话提示

### 实测额度特征
- 上游**不返回** `Retry-After`，也没有 `x-ratelimit-*` 头，只能盲试。
- 打满后立刻恢复一个名额约需 20s，完全恢复 60~110s；小请求（"hi"）也会被算进去。
- 限流是按 key 共享的，换模型不能绕（deepseek 429 时 glm-5.2 有时也 200 有时也 429，属于同一窗口）。

### 改动（`auto_code_llm_openai.go`）
- `openAIChat` 拆成外层重试 + `openAIChatOnce`（单次请求）。
- 429 包装成 `upstreamRateLimited` 类型，用 `errors.As` 判定可重试；
  退避 `8s → 25s → 40s`，重试 2 次（合计最长约 50s，覆盖一个恢复窗口）。
  用 `select` + `ctx.Done()` 等待，客户端断开能立刻退出。
- 重试用尽 → `rateLimitMessage()` 输出：点明 429 + 模型名 + 三条建议（等 1 分钟 / 换模型 / 换 key）+ 原始返回。
- 流式 `openAIStream` 不能重试，但会先读掉 429 body 并返回同一套提示（`retried=0` 时不谎称已重试）。
- 前端 `autoCode/index.vue`：加 `generating` / `recognizing` 两个 loading ref，
  按钮 `:loading` + `if (generating.value) return` 防连点（连点等于自己打满额度）；
  `JSON.parse` 包 try/catch，不再抛未捕获异常。

### 验证
- 预热 probe 打到 429，立刻点生成：日志出现 `上游限流，等待后重试 {"model":"deepseek-v4-flash","retry":1,"wait":8}`，
  18.07s 后返回 code=0、4 字段 —— 自动恢复成功。
- 单测 `TestRateLimitMessage` / `TestUpstreamRateLimitedIsRetryable` 通过（含"经 fmt.Errorf 包装后仍可识别"）。
